# S 方案接入与深度精度验证

## 1. 结论

最终存储格式采用 **近段线性、远段对数 + SZ3，逐帧 T1，米制 float32 接口**。默认 `alpha=0.002`：0–1 m 最多 2 mm 压缩误差，1–10 m 最多 0.2%；大于 10 m 原值无损保留。

S 格式已完成完整序列验证。默认误差档位是工程初始设置，**尚未通过独立真值证明其适合所有下游任务**。当前测试视频没有配套深度真值，不能报告 FFS 的真实测距误差。

## 3. 格式契约

对正常深度 `0 < z <= 10 m`，以米为数值单位：

```text
C(z) = z                 z <= 1
C(z) = 1 + ln(z)         z > 1

C_inv(t) = t             t <= 1
C_inv(t) = exp(t - 1)    t > 1

允许误差 E(z) = alpha * max(1,z) m
```

编码顺序：分离例外值 → 正常值变换为 C 域 float32 → SZ3 ABS 压缩 → 打包。默认变换域 `ABS=0.00199`，其他 alpha 使用 `0.995*ln(1+alpha)`，为浮点变换留余量。支持 alpha 范围 `[0.0001,0.1]`。

例外值为 `z>10`、`z<=0`、NaN、正负无穷。正常流中的例外位置用 1 填充；例外位置 bitmask 和对应 float32 原始位模式分别用 zlib 无损压缩。每个 chunk 包含版本魔数、三段长度和 CRC32，解码时检查长度和校验和，再逆变换并恢复例外值。保留 NaN 位模式和负零。

对外只有一个 `depth` 数组，形状 `(T,H,W)`，dtype float32，默认 chunks `(1,H,W)`，单位米。内部变换和例外值由 codec 自动处理。**float32 是容器和解码类型，不代表正常区域没有有损误差。**

新 ID：`centerdepth.log_sz3.v1`。旧 `centerdepth.sz3.v1` 保留，不把旧数据解释为新格式。读取前须安装 `zarr<3`、`numcodecs`、`pysz==1.0.3` 并导入 `stereo_center.depth_sz3`。不支持仅安装裸 Zarr 的读者。

旧 writer 把非有限值、负值归零；新 writer 逐位保留这些例外。下游仍应显式使用 `isfinite(depth) & (depth > 0)` 有效掩码。

`run_depth_video.py` 新增 `--depth-storage-alpha`，其他推理配置不变。视频仍直接使用压缩前深度着色，压缩器不修改输入。通过 Zarr 重新渲染的视频则使用解压深度，可能与压缩前视频有微小差异。

## 4. “测试深度估计精度”的含义

需要区分三个量：

| 对比 | 回答的问题 |
| --- | --- |
| 原始 FFS 深度 vs 独立真实距离 | 模型与完整标定/同步/推理系统测得准不准 |
| 解压深度 vs 原始 FFS 深度 | 存储额外损失多少信息 |
| 解压深度 vs 独立真实距离 | 下游真正拿到的数据还剩多少准确度 |

有符号误差满足 `e_total = e_model + e_storage`。误差可能抵消，也可能叠加，不能默认独立或认为解压能恢复原值。静态场景的逐像素时间标准差衡量重复性，不等于绝对准确度；一个稳定偏离真实距离 5 cm 的模型可以不闪烁，但仍不准确。

例如某距离段 FFS 本身 MAE=20 mm，并不自动意味着可以再加 20 mm 压缩误差。应验证压缩后总误差增量、偏差、异常点比例，以及下游任务是否越过可接受阈值。

不能从彩色 MP4、另一份 FFS 输出、重投影光度误差或压缩重建误差得出模型真实精度。与独立对齐参考深度逐像素评测是常见方法；例如 [KITTI 深度评测](https://www.cvlibs.net/datasets/kitti/eval_depth.php?benchmark=depth_prediction) 使用与图像对应的深度参考并报告相对误差等指标。公开数据集成绩不能替代当前奥比相机、标定及 TensorRT 配置的实测。

## 5. 采集与测试步骤

1. 固定当前奥比设备、双目标定、PTS 对齐、去畸变、scale=0.5、FFS TensorRT engine、迭代次数和输出视角。保存 engine、标定文件校验值及全部运行参数。
2. 准备独立参考。优先使用标定板/平面靶标的实测几何；或同步的深度传感器参考，注明其不确定度，不能把传感器输出当作完全无误差真值。
3. 采集约 0.3、0.5、0.8、1、1.2、2、3、5、10 m 的静态目标，以设备实际工作范围为准。每组至少 100 帧，覆盖画面中心/边缘及不同纹理、光照；另外采集遮挡边缘、细小结构和运动片段。
4. 参考值必须与**去畸变后的左相机像素、时间戳、光轴 Z 深度**一致。激光测距仪的径向距离不能直接铺满整幅图。已知平面在左相机坐标中为 `n^T X=d` 时，参考深度为 `z=d/(n^T K^-1 [u,v,1]^T)`；仅统计平面内且几何可靠的 ROI。不要用 FFS 预测拟合平面，再把该平面称为独立真值。
5. 运行推理并增加 `--save-depth-npy 1`，保存压缩前深度作为唯一基线。对同一基线测试 alpha=0.001、0.002、0.003，不重新推理后混用不同结果；不做重复有损转码。
6. 分别计算原始/解压深度相对参考的 MAE、RMSE、Bias、AbsRel、1/3/10 mm 坏点率和有效覆盖率，按 0–1、1–3、3–5、5–10、>10 m 分组。静态重复性另按固定像素统计时间波动。不要仅报告全片平均数。
7. 先规定下游可接受总误差及压缩后的额外退化预算，再选满足全部距离段条件且体积最小的档位。除均值外检查无效像素增加和边缘退化。参考测量不确定度若与所比较的档位差异相当，不应声称分辨出哪个档位更准确。

可先采用“各主要距离段 MAE/RMSE 相对原始预测增加不超过 5%，且不突破任务绝对误差上限”的试验筛选规则；5% 是待确认的工程预算，不是已验证标准。无效覆盖率不得下降；原始误差接近零时须另设绝对增量预算，不能机械套比例。

## 6. 评估工具

```bash
# 仅验证 S 存储，不需要 GT；source.zarr 应为压缩前无损基线。
python stereo_center/scripts/validate_depth_storage.py \
  source.zarr output_s2 --alpha 0.002

# 真正的深度准确度评测；三方必须预先完成时间、像素和单位对齐。
python stereo_center/scripts/evaluate_depth_accuracy.py \
  --prediction outputs/reference_run \
  --reference reference_depth_m.npy \
  --reconstructed outputs/reference_run/depth.zarr \
  --reference-kind ground_truth \
  --reference-description 'Measured plane in rectified left-camera coordinates' \
  --aligned-metric-z-confirmed \
  --output outputs/accuracy_s2.json
```

`--prediction` 可为 `--save-depth-npy 1` 生成的目录。三类输入均支持单个 `(T,H,W)` NPY、Zarr 的 `depth` 数组，或连续编号的 `depth_*.npy` 目录。`--mask` 可传入参考侧生成的同形状 bool NPY；`--reference-uncertainty-m` 记录测量不确定度。传感器参考使用 `--reference-kind sensor_reference`。

工具不自动缩放、配准或调整预测值，不把不一致形状强行缩放为一致。全参考有效区域分别报告原始/解压覆盖率；误差增量只在双方共同有效支持集上比较，避免以删除困难像素伪造提升。单位是米，比例是 0–1，报告保存参考来源；不同源的对齐正确性仍需采集者验证。
