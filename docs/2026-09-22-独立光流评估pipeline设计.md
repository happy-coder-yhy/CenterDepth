# 独立光流评估 Pipeline 设计

## 目标与边界

本设计建立一个独立于 FFS、深度估计、立体标定和清洗切片的光流评估
pipeline。它以相邻 RGB 帧对为输入，分别支持 SEA-RAFT 与 RoMa v2，输出可
审阅的视频可视化、原始光流、运行性能和可解释的质量诊断。它不修改 FFS
TensorRT engine，也不将任何光流结果回灌到深度。

首版回答两个不同的问题：

- 对可控合成平移，模型是否准确恢复已知光流。
- 对真实视频，模型是否产生时空上自洽、方向合理且性能可接受的光流。

真实视频没有光流真值时，不将重投影残差或前后向一致性称为准确率，不输出
AEPE、BadPix 等真值指标。

## 输入与数据契约

CLI 只支持两种互斥输入形式：

- `--video <mp4>`：按 `(t, t + frame_stride)` 组成帧对；默认
  `frame_stride=1`，视频输出帧率与输入视频一致。光流单位为
  `px / frame_stride`。
- `--image-a <path> --image-b <path>`：单一帧对，用于调试或定点对比。

输入经 OpenCV 解码后从 BGR 统一转换为 `float32 RGB [0,255]`，不进行 FFS
去畸变、双目校正或深度推理。两个图像必须具有相同宽高；不一致时在推理前
报错。模型的内部缩放必须将输出向量恢复到原始输入坐标中的像素单位。

`--synthetic-translation dx dy` 基于一张真实输入图构造已知平移的目标图，
并产生有效区域和遮挡区域掩码。它是首版唯一允许计算真值 AEPE、AE、
BadPix 和 KITTI-rule outlier 的输入模式。

## 统一推理与缓存流程

```text
video / image pair
  -> RGB 帧对解码与形状校验
  -> 模型、源码、权重缓存预检
  -> SEA-RAFT 或 RoMa v2 加载
  -> warm-up（不计入性能数据）
  -> 正向与反向光流推理
  -> flow_forward.npy / flow_backward.npy 缓存
  -> 全片统一的幅度 P99 标尺
  -> PNG 与 MP4 视频渲染
  -> metrics.json + manifest.json
```

视频必须先完成推理和原始光流缓存，再进行渲染。这样同一个向量在任意帧使用
同一套颜色与幅度范围，不会因为逐帧最大值不同导致颜色闪烁。用户可以通过
`--flow-color-max-px` 覆盖自动 P99 标尺；该数值会写入 manifest。

每个缓存元素使用 `float32`、形状 `(H, W, 2)`、通道顺序 `(u, v)`，其中
`u > 0` 表示向右，`v > 0` 表示向下。视频输入写成可追加的 NPY memmap，
避免完整视频常驻显存或内存。

## 视频可视化产物

对视频输入，输出目录包含以下无音频 MP4；所有视频逐帧对应输入帧对，尺寸
和 fps 固定，便于像深度视频一样直接连续播放与横向对比。

| 文件 | 每帧内容 | 目的 |
| --- | --- | --- |
| `flow_color.mp4` | Middlebury/Baker 色轮光流 | 方向和相对幅度的主视图 |
| `flow_magnitude.mp4` | 固定色标的幅度热力图与单位标注 | 比较实际位移大小 |
| `flow_arrows.mp4` | 原始 RGB 上的规则稀疏箭头 | 观察局部匹配和边缘运动 |
| `flow_diagnostics.mp4` | warp RGB 残差与前后向残差 | 发现遮挡、出界和错误对应 |
| `flow_report.mp4` | 2 x 3 总览：源帧、目标帧、色轮、幅度、箭头、诊断 | 快速审阅的默认视频 |

对单图对输入，输出相同名称的 PNG，而不是制造一帧 MP4。视频和 PNG 均额外
抽取首帧、中间帧、末帧为静态样本。

### 可视化方法选择

1. **Middlebury/Baker 色轮**：色相编码方向，色彩强度编码幅度，是 RAFT 与
   SEA-RAFT 官方示例使用的通用比较方式。零流为白色，无效值为黑色。
2. **幅度热力图**：使用感知连续色图和全片固定 `vmax`，不得使用每帧自动
   min/max。它保留绝对 px/frame 的可比性，但不携带方向。
3. **稀疏箭头**：按固定像素间隔采样，箭头长度按物理像素向量绘制；过密
   或过小向量不绘制，避免把纹理变成噪声。
4. **warp/前后向诊断**：用反向流将目标帧采样到源帧，显示绝对 RGB 残差，
   再显示 `||F_01 + warp(F_10)||`。出界和无效采样使用掩码，不以边界复制
   伪造低残差。

SEA-RAFT 的 `info` 和 RoMa v2 的 `overlap` 分别保存为后端专属 `.npy` 辅助
产物。首版不将它们等价为统一置信度，也不以其阈值掩盖光流图；待各自语义在
目标数据上验证后再增加独立的后端诊断面板。

## 指标与性能报告

`metrics.json` 按帧对和全片汇总以下内容：

- 所有输入：推理耗时 mean/median/P95/P99、有效吞吐 FPS、CUDA peak reserved
  memory、幅度 mean/median/P95/P99、前后向一致性有效率和 RGB warp MAE。
- 合成真值：复用现有 `flow_metrics.py` 的 AEPE、EPE P95、mean AE、方向 AE、
  BadPix 1/3/5、KITTI-rule outlier，并按有效、遮挡、位移区间分组。

CUDA 计时在每个模型调用边界同步；warm-up 帧对只用于编译、缓存和显存稳定，
永不计入上述性能分位数。`manifest.json` 记录 CLI 参数、输入 hash/帧率、模型
源码 revision、权重路径/哈希、包版本、GPU 名称和色标参数。

## 验收与测试

1. CPU 单元测试不加载真实模型或权重：验证数组契约、色标稳定性、warp 方向、
   指标边界与 manifest 内容。
2. A100 每个后端做两帧 smoke：验证本地资产可离线加载、输出有限值、五个视频
   可解码、manifest 权重哈希正确。
3. A100 每个后端跑同一段短视频：比较每对耗时、P95/P99、显存、前后向残差和
   统一色标下的 `flow_report.mp4`。
4. 合成的水平、垂直、斜向平移分别运行：检查真值 AEPE/BadPix 输出和遮挡区
   不被当作有效真值像素。
